# Демо-счета

Две разные вещи, и обе нужны:

| | Что это | Кто делает |
|---|---|---|
| **Внутренние виртуальные счета** | Уже работают. Проект сам открывает каждый опубликованный сигнал по опубликованным уровням и ведёт учёт | готово, ничего делать не надо |
| **Внешние демо-счета брокеров** | MT5 demo (MOEX/FORTS), Bybit testnet (крипта) — реальный стакан, виртуальные деньги | регистрируете вы |

---

## 1. Внутренние счета (работают)

```bash
python scripts/paper_sync.py --trades
```

Три счёта заведены автоматически:

| Счёт | Депозит | Риск на сделку | Фильтр |
|------|---------|----------------|--------|
| Основной 100k ₽ | 100 000 ₽ | 1% | все сигналы |
| Только сильные сигналы | 100 000 ₽ | 1% | WEF ≥ 65% |
| Агрессивный 2% | 100 000 ₽ | 2% | все сигналы |

Три счёта, а не один, специально: если «Только сильные» обгонит «Основной», это
первое реальное подтверждение, что WEF Score что-то предсказывает. Если не обгонит —
значит балл не работает, и это надо будет признать.

Правила зафиксированы заранее и видны в API — `GET /api/v1/paper/methodology`.
Ключевое: уровни копируются в сделку при открытии и потом не меняются, поэтому
поздняя правка сигнала не может изменить записанный результат.

Смотреть:

```bash
curl http://localhost:8000/api/v1/paper/accounts
curl "http://localhost:8000/api/v1/paper/trades?status=closed&limit=20"
```

Синхронизация в cron стоит на `:25` каждый час — сразу после монитора сигналов
(`:17`), чтобы закрытый сигнал в тот же час становился сделкой с деньгами.

## 2. MT5 demo

Мост к MT5 в проекте уже есть (`mt5/` + `services/mt5_bridge.py`), ему нужен счёт.

### Сначала главное: демо надо выбирать по инструментам

Замер состава сигналов платформы (`scripts/`, по своей же базе, 122 реальных
сигнала):

| Класс | Доля | Активных сейчас |
|---|---|---|
| MOEX + неопознанные 4–5 букв (RU/US акции) | 57% | 11 |
| US/EU акции | 34% | 2 |
| Фьючерсы MOEX FORTS | 4% | **4** (BR-9.26, GAZR-9.26, RTS-9.26, VTBR-9.26) |
| Крипта (Binance) | 6% | 0 |

**В стандартном демо MT5 у форекс-брокера ничего из MOEX и FORTS нет.**
MetaQuotes-Demo, Alpari, RoboForex дают форекс, металлы, индексы и CFD — то есть
почти ни один сигнал платформы на них не исполнится. Это делает такой счёт
бесполезным для измерения, хотя он и открывается за минуту.

Поэтому счётов нужно два, и в таком порядке.

### Шаг 1. MetaQuotes-Demo — отладить связку сегодня

Цель — не измерение, а проверка, что цепочка вообще работает: токен, соединение,
`cmd=signal`, запись в базу, факт исполнения.

1. Скачать терминал — [metatrader5.com/ru/download](https://www.metatrader5.com/ru/download)
2. **Файл → Открыть счёт** → в списке серверов `MetaQuotes-Demo` → тип **Demo**
3. Депозит 100 000, плечо **1:10** — не выше, иначе расчёт размера позиции
   (`services/position_sizing.py`) теряет смысл
4. Выписать `login` / `password` / `server`
5. Советник на график `EURUSD` H1 — единственный класс, который на этом сервере
   точно есть и который платформа умеет оценивать

На этом счёте `AutoTrade=false`. Задача шага — увидеть в логе терминала строку
`Платформа: WEF NN% | вердикт ...`, то есть что сигнал доехал и прошёл гейт.

### Шаг 2. Российский брокер с MOEX и FORTS — для измерения

Здесь исполняются настоящие сигналы платформы.

Из проверенного: MT5 с доступом к Московской бирже, включая срочный рынок, дают
российские брокеры — **ФИНАМ** (единый счёт, MOEX + NYSE/Nasdaq) и **Открытие**
(первым запустил торговлю на MOEX через MT5). Оба поддерживают демо.

**Что уточнить у брокера до открытия** — от этого зависит, годится ли счёт:

- есть ли на демо **срочный рынок FORTS** (нужны `BR`, `GAZR`, `RTS`, `VTBR`), а не
  только валютный
- доступен ли **рынок акций MOEX** на MT5, или только валюта и срочный
- нужен ли реальный брокерский договор **до** выдачи демо
- срок жизни демо-счёта (часто 30 дней с продлением)

И одна вещь, которую надо просто посмотреть в терминале и сказать мне: **как именно
пишутся тикеры фьючерсов**. Платформа ждёт формат `BR-9.26`, а ISS MOEX внутри
работает через SECID `BRU6`. Если ваш брокер называет контракт иначе, я допишу
сопоставление в `normalize_symbol` — иначе повторится история с `BR-8.26`, когда
данных молча не было.

### Что вставить в `backend/.env`

```env
MT5_BRIDGE_TOKEN=<сгенерировать: python -c "import secrets; print(secrets.token_urlsafe(32))">
```

Тот же токен — в поле `BridgeToken` советника. Логин и пароль от счёта в `.env`
проекта **не нужны**: советник сам подключается к мосту, а сделки выставляет
терминал, у которого доступ к счёту уже есть. Мост про счёт ничего не знает и знать
не должен.

### Про Windows

Терминал MT5 — только Windows. Но сам мост — обычные сокеты, он работает и на
Linux-VPS: советник подключается к нему по сети. Тогда `MT5_BRIDGE_TOKEN`
обязателен, иначе мост откажется слушать непетлевой интерфейс.

Библиотека `MetaTrader5` для Python (прямое управление терминалом) в этой
архитектуре не используется — она действительно только под Windows, но она нам не
нужна.

## 3. Bybit testnet — для крипты предпочтительнее

Крипта в проекте теперь берёт цены и свечи из двух источников (Binance и Bybit) с
автоматическим фолбэком, а Bybit доступен из России, откуда Binance ушёл. Поэтому
для крипто-измерения смотрите сначала на Bybit.

**Что делаете вы:**

1. [testnet.bybit.com](https://testnet.bybit.com) → регистрация (отдельная от боевого аккаунта)
2. Профиль → **API** → создать ключ, разрешения: **Read-Write**, тип **Unified Trading**
3. Сохранить `API Key` и `Secret` (секрет показывается один раз)

**Что вставить в `backend/.env`:**

```env
CRYPTO_PRIMARY=bybit
```

Сами ключи вводятся не в `.env`, а через интерфейс проекта: Исполнение → подключить
счёт. Они шифруются `ENCRYPTION_KEY` перед записью в базу.

Важно: у подключённого счёта флаг `is_testnet` по умолчанию **включён**. Снять его —
отдельное осознанное действие; пока у платформы 11 измеренных сделок и ни одной
прибыльной, торговать реальными деньгами по её сигналам не стоит. Для биржи без
режима testnet (например Т-Инвестиции) счёт, помеченный виртуальным, уходит на
демо-адаптер, а не получает живые ключи.

## 4. Binance testnet

Полностью бесплатно, отдельная сеть, реальный стакан.

**Что делаете вы:**

1. [testnet.binance.vision](https://testnet.binance.vision) → войти через GitHub
2. **Generate HMAC_SHA256 Key** → сохранить `API Key` и `Secret Key`
   (секрет показывается один раз)

**Что вставить в `backend/.env`:**

```env
BINANCE_TESTNET=true
BINANCE_API_KEY=...
BINANCE_API_SECRET=...
```

Ключи тестнета не работают на боевом API и наоборот — перепутать не опасно, просто
не подключится.

## 5. MOEX

Демо-счёта с API у российских брокеров либо нет, либо он требует открытого
брокерского счёта (Финам, Т-Инвестиции). Для MOEX внутренние виртуальные счета
остаются единственным вариантом, и этого достаточно: котировки берутся с
ISS API MOEX — те же данные, что у брокера.

## Чего демо-счета не покажут

Стоит помнить при чтении результатов:

- **Проскальзывание и спред.** Виртуальная сделка исполняется точно по уровню.
  Реальная — хуже, особенно на неликвиде. На дистанции это съедает часть результата.
- **Комиссии.** Не учитываются. При 1% риска на сделку и частой торговле комиссия
  заметна.
- **Психология.** Виртуальный стоп исполняется всегда. Реальный человек его
  переставляет.
- **Ликвидность.** Расчётная позиция может не набраться на тонком инструменте.

Поэтому демо-результат — это верхняя граница, а не ожидание. Реальный результат
будет ниже, и когда наберётся выборка, разницу надо будет измерить, а не
предполагать.
