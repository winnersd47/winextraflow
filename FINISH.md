### 1.2. Перевыпустить токен бота

Прежний лежал в открытом виде в двух скриптах. Считается скомпрометированным.
@BotFather → `/revoke` → новый в `backend/.env` → `TELEGRAM_BOT_TOKEN`.

Проверка: `/api/v1/public/data-status` покажет `Telegram API: degraded` с текстом
«Bot token rejected — reissue it», пока новый токен не встанет на место.

### 1.3. Публиковать статьи целиком в канале

Ссылки на `pages.dev` из РФ не открываются, поэтому тизер со ссылкой сейчас
бесполезен. Полный текст в канале работает уже сегодня:

```bash
python scripts/lesson_post.py --full --slug=stop-po-atr
```

Шесть материалов, по одному в два-три дня — хватит на две недели. Тизеры со
ссылкой (`lesson_post.py` без `--full`) включать после переезда фронта.

### 1.4. SMTP

Без него подтверждение почты при регистрации не работает вовсе — письма уходят в
лог. Бесплатные тарифы есть у Яндекс 360 и Brevo (300 писем/сутки). Заполнить
`SMTP_*` в `.env`.

### 1.5. Три документа по соответствию

Из восьми незакрытых пунктов три — бумажная работа, а не расходы, и их всё равно
придётся сделать до денег:

| Пункт | Что нужно |
|---|---|
| `personal_data_operator` | уведомление в РКН об обработке ПДн (152-ФЗ), подаётся онлайн, бесплатно |
| `aml_policy` | правила внутреннего контроля по 115-ФЗ — написать |
| `kyc_procedure` | регламент идентификации клиентов — написать; технический модуль уже есть |

Остальные пять (`securities_license`, `crypto_license`, `liability_insurance`,
`gdpr_compliance`, `okved_extract`) к информационно-аналитическому сервису либо не
относятся, либо не требуются — но статус у них надо выставить осознанно, а не
оставлять «в работе».

## 2. Идёт само — не трогать

**19 сделок до порога.** Это единственное, что нельзя ускорить работой. Конвейер
работает: 25 активных сигналов, 65 виртуальных позиций, 12 задач в расписании.

Что смотреть и когда:

```bash
python scripts/wef_validation.py      # 1-го числа сам, вручную — когда захочется
python scripts/paper_sync.py --trades # текущее состояние счетов
```

Когда наберётся 30, произойдёт одно из двух:

- **«Только сильные сигналы» обгонит «Основной»** — первое подтверждение, что WEF
  Score что-то предсказывает. Тогда есть смысл в домене, VPS и кассе.
- **Не обгонит** — балл не разделяет сделки по результату. Это тоже результат:
  значит менять надо оценку, а не докупать инфраструктуру.

Оба ответа полезны. Плохой вариант только один — включить кассу до ответа.

## 3. Когда появятся деньги (и смысл их тратить)

Порядок именно такой — каждый пункт бессмыслен без предыдущего.

1. **Домен `.ru`** — 200–1000 ₽/год. Самый дешёвый пункт и единственный, где
   экономия создаёт риск: вебхук ЮKassa должен жить на домене, который вы
   контролируете.
2. **VPS в РФ из реестра РКН** — RuVDS (~1149 ₽/мес, есть заключение о
   соответствии 152-ФЗ) или Timeweb (900 ₽/мес). Дальше по [DEPLOY.md](deploy/DEPLOY.md).
3. **$10 на OpenRouter** — поднимает лимит с 50 до 1000 запросов в сутки. После
   этого `LLM_PARSE_PER_RUN` можно вернуть с 1 на 10.
4. **ЮKassa** — только после того, как измерение показало положительное ожидание.
   Флаг `PAID_SUBSCRIPTIONS_ENABLED` не трогать до этого момента.

Промежуточный бесплатный вариант, если публичный сайт нужен раньше: Oracle Cloud
Always Free плюс бесплатный поддомен. Работает, но серверы не в РФ — годится, пока
касса выключена и живых пользователей нет, и требует переезда до первого из двух.

1. 30 измеренных сделок, и известно, предсказывает ли WEF Score результат

надежда, и именно поэтому она выключена.
